# RAG + Tool Calling Agent - Prompt 工程记录

> 本文档记录本项目实际使用的 Prompt 结构、设计理由、Few-shot、输出格式控制、异常处理，以及开发过程中的 3 组 Prompt 对比。对应代码见 `backend/agent.py`。

## 1. Prompt 结构

### 1.1 Agent System Prompt

| 元素 | 内容 |
|------|------|
| 角色 | 智能 AI 助手，可调用工具、检索知识库 |
| 任务 | 回答用户问题；必要时先检索知识库或调用工具 |
| 上下文 | 当前日期（服务器时间动态注入）、可用工具与能力边界 |
| 输入 | 用户问题、对话历史、工具调用结果 |
| 输出格式 | 自然语言回答；需要执行工具时输出结构化 `tool_calls`（name + arguments JSON） |
| 约束 | 先思考再行动；调用工具前说明理由；不确定不编造；引用来源；无法获取时直接说不知道 |

### 1.2 RAG System Prompt（检索成功后切换）

| 元素 | 内容 |
|------|------|
| 角色 | 基于文档回答的 AI 知识助手 |
| 任务 | 根据注入的检索上下文回答用户问题 |
| 上下文 | Chroma + BM25 混合检索结果，含来源文件名、相关度与片段 |
| 输入 | 用户问题 + “以下是知识库检索结果”上下文 |
| 输出格式 | 简洁、清晰的最终回答，标注引用 |
| 约束 | 只基于文档回答；必须引用来源；未找到时明确拒答；不确定不猜测 |

## 2. System Prompt 设计理由

- Agent 使用动态日期，避免模型把“当前时间”当成训练截止时间；同时显式声明工具能力和决策规则，减少无关工具调用。
- RAG 检索成功后才切换到 RAG System Prompt，避免普通对话也被“只基于文档”约束；切换后模型必须引用来源，从提示词层面降低幻觉。
- 两个 Prompt 都包含“不确定时拒绝/承认不知道”，与工具结果和检索阈值形成三层兜底。
- 不硬编码 Few-shot 示例，原因是工具 Schema 已经携带名称、描述、参数类型，且不同供应商对示例格式敏感；使用评估问题集作为可重复验证的参考。

## 3. Few-shot 策略

- 未在 System Prompt 中硬编码问答示例，而是通过工具 Schema 驱动模型生成结构化调用。
- 评估问题集 `data/test_questions/测试问题集.md` 提供 25 条带预期行为的 Few-shot 验证样本，覆盖知识检索、计算、搜索、时间、混合、拒绝与综合场景。
- 若模型对某类工具选择率持续偏低，会先优化工具 description/parameters，再考虑追加示例。

## 4. 输出格式控制

- OpenAI 兼容接口：使用 `tools` 参数返回结构化 `tool_calls`，流式响应按 `delta.tool_calls` 增量拼接。
- 参数校验：`json.loads` 解析工具参数，必须是 JSON 对象；解析失败时把“错误信息 + 原始参数”作为 `role="tool"` 消息回灌，让模型修正重试。
- Anthropic 接口：将 `tool_use` block 转为统一的 `tool_calls` 结构，参数解析失败时保留 `_parse_error` 兜底。
- ReAct 循环上限 5 轮；达到上限仍未产出最终回答时，返回明确兜底文案并记录 warning。

## 5. 不确定/越界/格式错误处理

| 场景 | 处理方式 |
|------|----------|
| 文档中无相关信息 | RAG Prompt 要求明确说“在已导入文档中未找到相关信息” |
| 模型不确定 | 要求不猜测、不编造，直接承认不知道 |
| 工具参数 JSON 解析失败 | 以 tool 消息回灌原始参数和错误，模型修正后重试 |
| 工具执行异常 | 捕获异常并返回 `{"success": false, "error": ...}`，模型继续决策 |
| ReAct 超过 5 轮 | 返回兜底回答并记录 warning |
| 未知供应商/缺 API Key | 启动或调用时抛出明确错误，前端提示配置 |

## 6. Prompt 对比（3 组）

### 6.1 RAG System Prompt：从“尽量回答”到“只基于文档 + 引用 + 拒答”

| 版本 | Prompt 关键内容 | 效果 |
|------|----------------|------|
| V1 | 根据文档内容尽量回答用户问题 | 相关时能答，但检索不相关时容易发挥、出现幻觉；引用不稳定 |
| V2（当前） | 只基于提供的文档内容回答；必须引用来源；未找到时明确说“在已导入文档中未找到相关信息”；不确定不猜测 | 拒绝质量提升，幻觉明显下降，回答可溯源 |

### 6.2 工具参数 JSON 解析失败：从“直接丢弃”到“错误回灌重试”

| 版本 | 处理方式 | 效果 |
|------|----------|------|
| V1 | 解析失败时丢弃该次调用并继续，模型可能反复输出相同坏参数 | 工具调用成功率低，偶发死循环 |
| V2（当前） | 把“JSON 解析失败 + 原始参数”作为 `role="tool"` 消息回灌 | 模型能在下一轮修正参数，工具调用一次成功率明显提升 |

### 6.3 ReAct 循环上限：从“无上限/2 轮”到“5 轮 + 兜底”

| 版本 | 处理方式 | 效果 |
|------|----------|------|
| V1 | 无硬上限，依赖模型自然结束 | 复杂任务偶发长时间循环、Token 消耗不可控 |
| V2 | 固定 2 轮，过早截断 | 需要多工具组合的任务经常拿不到最终答案 |
| V3（当前） | 上限 5 轮；达到上限且没有最终回答时返回兜底文案并记录 warning | 常见 RAG+计算+搜索组合任务可在预算内完成，异常循环有明确出口 |
