## 2. 核心模块设计

### 2.1 文档解析模块 (document_loader.py)
- 支持 PDF 解析 (pymupdf)
- 支持 Markdown/TXT 文本解析（纯文本提取）
- 支持 TXT 文本解析
- 输出统一结构: {title, content, metadata, source}

### 2.2 文本切分模块 (text_splitter.py)
- 策略1: 递归字符切分 (RecursiveCharacterTextSplitter)
  - chunk_size=500, chunk_overlap=50
- 策略2: Markdown 结构切分 (Header-aware)
  - 按标题层级保持语义完整性
- 策略3: 语义切分 (按段落/自然边界)
- 输出: List[DocumentChunk] = {id, text, metadata}

### 2.3 嵌入与检索模块 (retriever.py)
- Embedding 生成: OpenAI text-embedding-ada-002 / text-embedding-3-small
- 向量存储: Chroma (本地持久化)
- 检索策略:
  - 基础向量检索 (Top-K=5)
  - 混合检索（向量 + BM25）排序；当前未实现 MMR 去重
  - 相似度阈值过滤
- 支持元数据过滤 (按文档来源过滤)

### 2.4 Agent 模块 (agent.py)
- 核心循环:
  1. 接收用户问题
  2. 决定行动: 检索知识库 / 调用工具 / 直接回答
  3. 执行所选行动
  4. 整合上下文生成回答
  5. 记录完整思考过程
- 状态管理: 对话历史、推理跟踪、工具记录

### 2.5 工具模块 (tools.py)
- calculator: 数学运算
- get_current_time: 时间查询
- web_search: 网页搜索
- query_docs: 在已导入文档中搜索

### 2.6 记录模块 (logger.py)
- reasoning 摘要、工具调用详情、最终回答、Token 用量、耗时

### 2.7 动态供应商客户端
- 内置供应商继续从 `backend/config.py` 的 `LLM_CONFIGS` 读取；网页自定义供应商通过请求体 `provider_config` 传入。
- 自定义供应商只存活于单次请求：Agent 对话、RAG 检索、上传文档均按需创建 OpenAI 兼容客户端（`anthropic_style=true` 时走 Anthropic 客户端）。
- API Key 不写入日志、历史、向量 metadata 与响应；后端统一脱敏，前端仅保存在 `sessionStorage`。
- `GET /v1/models` 只返回内置供应商，前端合并自定义供应商，因此新增供应商无需重启服务。

### 2.8 向量库 Profile 与重建
- Chroma 集合 metadata 保存 `embedding_provider`、`embedding_model`、`embedding_dimensions`。
- 首次入库写入 profile；已有索引时校验模型与维度，不一致返回 409 并提示重建。
- `GET /v1/vector-store/profile` 返回当前模型、维度、片段数、文档数。
- `POST /v1/vector-store/rebuild` 必须 `confirm=true`，清空向量库与 profile，供切换 Embedding 模型后重新入库。

## 4. API 接口
- GET /health - 健康检查
- GET /v1/models - 可用模型列表
- POST /v1/providers/test - 测试网页供应商连接（chat / embedding）
- GET /v1/vector-store/profile - 向量库 Embedding profile 与统计
- POST /v1/vector-store/rebuild - 重建向量库（confirm=true）
- POST /v1/documents/upload - 上传文档（全部成功 200；部分入库 202；失败 4xx/5xx）
- GET /v1/documents - 文档列表
- DELETE /v1/documents/{id} - 删除文档
- POST /v1/rag/query - RAG 检索
- POST /v1/agent/chat - Agent 普通对话
- POST /v1/agent/chat/stream - Agent SSE 流式对话
- POST /v1/tools/execute - 工具执行（业务失败 422）
- GET /v1/tools - 工具列表
- GET /v1/agent/logs - Agent 日志
- GET /v1/redis/info - Redis 信息
- GET /v1/redis/health - Redis 健康状态
- GET /v1/stats - 系统统计

## 5. Prompt 工程策略
- RAG System Prompt: 只基于文档回答+引用来源+不确定拒绝
- Agent System Prompt: 自主决策+先思后行+工具调用解释
- Few-shot: 不硬编码示例，通过工具 Schema 驱动；评估问题集提供参考

- 当前 60 个自动化测试全部通过，覆盖 API、鉴权、限流、文档解析、文本切分、混合检索、Agent 工具循环、流式 SSE、上传成功/部分入库与回滚、供应商测试、向量库 profile 与重建、API Key 脱敏
- 测试使用 Mock 与临时目录，不依赖真实模型 API 或外网
- 质量门禁: `python -m pytest tests/ -v`、`python -m ruff check backend/`
- 评估问题集见 `data/test_questions/`
